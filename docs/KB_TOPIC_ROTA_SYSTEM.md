## Overview

The KB Topic Rota System is a **perpetual, data-driven system** that:
1. **Discovers topics hierarchically** from Knowledge Base articles using multi-level clustering
   - **Level 1:** Broad themes (e.g., "Tartan Design")
   - **Level 2:** Granular sub-topics (e.g., "Line Widths and Balance in Tartan Design")
2. **Uses semantic understanding** via LLM-based topic naming (not keyword-based)
3. **Generates diverse weekly schedules** ensuring non-repetitive content
   - **Default:** Includes all topics in 2.8-year rotation (144 weeks for 144 topics)
   - **Configurable:** Can generate shorter rotations (e.g., 52 weeks)
4. **Aggregates content** from multiple KB articles for each topic
5. **Feeds social media production** processes for channel-specific formatting
6. **Self-updates** automatically as new KB content is added

## Database Schema

### Tables

#### 1. `kb_topics`
Stores discovered topics from KB clustering with hierarchical structure.

**Key Fields:**
- `id` - Primary key
- `topic_name` - Semantic topic name generated by LLM (e.g., "Tartan Design Principles", "Line Widths and Balance in Tartan Design")
- `topic_description` - Brief semantic description of the topic
- `topic_keywords` - Array of keywords extracted from cluster
- `embedding_vector` - Topic centroid embedding (1024 dimensions)
- `article_ids` - Array of KB article IDs belonging to this topic
- `category_ids` - Array of category IDs this topic spans
- `topic_type` - Classification: 'practical', 'historical', 'cultural', 'design', 'product', etc.
- `parent_id` - Foreign key to parent topic (NULL for Level 1, references another topic for Level 2)
- `level` - Hierarchical level: 1 (broad themes) or 2 (granular sub-topics)
- `is_broad` - Boolean: TRUE for Level 1, FALSE for Level 2
- `is_active` - Whether topic is active in rota

**Indexes:**
- `idx_kb_topics_active` - On `is_active` (partial, where active)
- `idx_kb_topics_priority` - On `priority, is_active`
- `idx_kb_topics_article_ids` - GIN index on `article_ids`
- `idx_kb_topics_category_ids` - GIN index on `category_ids`

#### 2. `kb_topic_similarity`
Pre-computed similarity between topics for diversity scheduling.

**Key Fields:**
- `topic1_id`, `topic2_id` - Topic pair (with constraint topic1_id < topic2_id)
- `similarity_score` - Cosine similarity (0.0 to 1.0)
- `distance` - L2 distance between embeddings

**Indexes:**
- Primary key on `(topic1_id, topic2_id)`
- `idx_topic_similarity_score` - On `similarity_score`

#### 3. `kb_topic_rota`
Weekly schedule of topics.

**Key Fields:**
- `id` - Primary key
- `topic_id` - Foreign key to `kb_topics`
- `scheduled_year`, `scheduled_week` - ISO week identifiers
- `scheduled_date` - First day of week (Monday)
- `diversity_score` - How diverse from recent topics (0.0 to 1.0)
- `status` - 'scheduled', 'ready', 'published', 'skipped'

**Constraints:**
- Unique on `(scheduled_year, scheduled_week)`

#### 4. `kb_rota_history`
History of posted topics for diversity tracking.

**Key Fields:**
- `rota_id` - Foreign key to `kb_topic_rota`
- `topic_id` - Foreign key to `kb_topics`
- `posted_date` - Date when topic was posted
- `similarity_to_previous` - Similarity to previous week topic

#### 5. `kb_topic_content`
Aggregated content from multiple KB articles for each topic.

**Key Fields:**
- `id` - Primary key
- `topic_id` - Foreign key to `kb_topics`
- `rota_id` - Foreign key to `kb_topic_rota` (optional)
- `aggregated_text` - Combined text content
- `source_article_ids` - Array of KB article IDs that contributed
- `source_chunk_ids` - Array of `content_chunks.id` used
- `content_hash` - MD5 hash for change detection
- `word_count` - Word count of aggregated text

## Core Modules

### 1. Clustering Engine (`utils/kb_topic_discovery/clustering.py`)

**Class:** `KBTopicClusterer`

**Methods:**
- `discover_topics()` - Main discovery method
  - Supports: 'kmeans', 'dbscan', 'hierarchical' clustering
  - Auto-detects optimal cluster count for K-means
  - Returns list of topic dictionaries

**Clustering Algorithms:**
- **K-means:** Auto-detects optimal k using silhouette score
- **DBSCAN:** Density-based clustering (eps=0.5, min_samples=3)
- **Hierarchical:** Agglomerative clustering with cosine distance

**Topic Extraction:**
- **LLM-Based Semantic Naming:** Uses Ollama (llama3.2:latest) to generate meaningful topic names from article content
  - Understands meaning and concepts, not just keywords
  - Generates contextualized names (e.g., "Line Widths and Balance in Tartan Design")
- Keyword extraction using frequency analysis (for metadata)
- Topic type classification (practical, historical, cultural, design, product)
- Category ID extraction from articles

### 1b. Hierarchical Discovery (`utils/kb_topic_discovery/hierarchical_discovery.py`)

**Class:** `HierarchicalTopicDiscoverer`

**Methods:**
- `discover_hierarchical_topics()` - Multi-level topic discovery
  - **Level 1:** Discovers broad themes using K-means clustering
  - **Level 2:** For each broad theme, discovers granular sub-topics using hierarchical clustering with tighter thresholds
  - Returns hierarchical topic structure with parent-child relationships

**Parameters:**
- `broad_clusters` - Number of broad theme clusters (default: 10-15)
- `granular_threshold` - Similarity threshold for granular sub-clustering (default: 0.80-0.90, higher = more specific)
- `min_broad_size` - Minimum articles for broad topics (default: 6-10)
- `min_granular_size` - Minimum articles for granular sub-topics (default: 2-3)

**Example Output:**
- **Level 1:** "Tartan Patterns & Variations" (119 articles)
  - **Level 2:** "Tartan Pattern Design and Layout" (2 articles)
  - **Level 2:** "Tartan Sett Arrangement Principles" (6 articles)
  - **Level 2:** "Line Widths and Balance in Tartan Design" (discovered from articles)

### 2. Similarity Calculator (`utils/kb_topic_discovery/similarity.py`)

**Class:** `TopicSimilarityCalculator`

**Methods:**
- `compute_similarity_matrix()` - Calculate pairwise similarities
- `get_similarity()` - Retrieve similarity from database

**Similarity Metric:**
- Cosine similarity between topic centroid embeddings
- Stored in `kb_topic_similarity` table

### 3. Diversity Manager (`utils/kb_topic_discovery/diversity.py`)

**Class:** `DiversityManager`

**Methods:**
- `calculate_diversity()` - Calculate diversity score for a topic
  - Considers similarity to recent topics
  - Bonuses for different topic types
  - Bonuses for different category areas
  - Penalties for too-similar topics

**Diversity Scoring (Enhanced 2026-01-23):**
- Base score: `1.0 - min_similarity` (lower similarity = higher diversity)
- **Strong Penalties for Consecutive Weeks:**
  - Same topic type: 70% penalty (diversity_score × 0.3)
  - Same parent topic: 80% penalty (diversity_score × 0.2)
  - High similarity (>0.75): 60% penalty (diversity_score × 0.4)
  - Moderate similarity (>0.65): 40% penalty (diversity_score × 0.6)
- **Bonuses:**
  - Different topic type: +0.2 (increased from 0.15)
  - Different parent topic: +0.15
  - Different category areas: +0.1 × (1 - overlap)
- **Safety Cap:** Diversity score capped at 0.3 for consecutive similar topics
- **Overall Penalty:** *0.5 if min_similarity > threshold

### 4. Rota Generator (`utils/kb_topic_discovery/rota_generator.py`)

**Class:** `RotaGenerator`

**Methods:**
- `generate_rota()` - Generate weekly rota with diversity constraints
  - Parameters:
    - `start_date` - First Monday of rota
    - `weeks` - Number of weeks (None = auto-calculate to include all topics)
    - `lookback_weeks` - How many recent weeks to check for diversity (default: 4, reduced for more focused diversity)
    - `min_similarity_gap` - Minimum similarity threshold to avoid (default: 0.65, stricter to prevent repetition)
    - `include_all_topics` - If True and weeks=None, generates rota to include all topics (default: True)
  - Returns list of rota entry dictionaries
- `save_rota()` - Save rota entries to database

**Rota Generation Algorithm:**
1. Get active topics
2. Auto-calculate weeks if `include_all_topics=True` and `weeks=None` (weeks = number of topics)
3. Get recent topics (lookback window)
4. Track unused topics (for ensuring all topics are included)
5. For each week:
   - Prioritize unused topics if `include_all_topics=True`
   - Filter candidates (exclude recently used)
   - Calculate diversity scores
   - Select topic (weighted random favoring diversity and unused topics)
   - Update recent topics list and usage tracking
6. Save to database

**Default Behavior:**
- **Includes all topics:** By default, generates a rota that includes all 144 topics (144 weeks = 2.8 years)
- **Ensures coverage:** All topics are guaranteed to appear at least once
- **Maintains diversity:** Still enforces similarity constraints to avoid repetitive content

### 5. Content Aggregator (`utils/kb_topic_discovery/content_aggregator.py`)

**Class:** `TopicContentAggregator`

**Methods:**
- `aggregate_content()` - Aggregate content from topic articles
  - Ranks chunks by relevance to topic centroid
  - Selects top N chunks
  - Combines with clear separators
- `save_aggregated_content()` - Save to database

**Aggregation Process:**
1. Get articles for topic
2. Retrieve chunks for articles
3. Generate embeddings for chunks
4. Rank by similarity to topic centroid
5. Select top N chunks
6. Combine with article structure preserved

## API Endpoints

### Base URL: `/api/kb-topics`

#### `GET /api/kb-topics/rota`
Get weekly rota schedule.

**Query Parameters:**
- `year` (optional) - Year (default: current year)
- `week` (optional) - ISO week number (default: current week)

**Response (when topic exists):**
```json
{
  "success": true,
  "topic": {
    "id": 277,
    "name": "Kilt Identity for Men: Cultural Significance",
    "description": "This topic covers...",
    "keywords": ["kilts", "kilt", "wearing", ...],
    "type": "cultural",
    "article_ids": [640, 329, 641, 350],
    "category_ids": [118, 123, 218]
  },
  "schedule": {
    "year": 2026,
    "week": 5,
    "date": "2026-01-26",
    "status": "scheduled",
    "diversity_score": 1.0
  },
  "content": null
}
```

**Response (when no topic exists):**
```json
{
  "success": false,
  "message": "No rota entry found for year 2026, week 4",
  "year": 2026,
  "week": 4
}
```

**Note:** Returns HTTP 200 OK in both cases (not 404) to prevent browser console errors.

## Scripts

### 1. `scripts/discover_kb_topics.py`
Manual topic discovery script (single-level clustering).

**Usage:**
```bash
python scripts/discover_kb_topics.py \
  --method kmeans \
  --n-clusters 20 \
  --min-cluster-size 3 \
  --compute-similarity
```

**Options:**
- `--method` - Clustering method: 'kmeans', 'dbscan', 'hierarchical'
- `--n-clusters` - Number of clusters (auto-detect if not specified)
- `--min-cluster-size` - Minimum cluster size (default: 3)
- `--similarity-threshold` - Similarity threshold for hierarchical (default: 0.7)
- `--compute-similarity` - Compute and store similarity matrix

### 1b. `scripts/discover_hierarchical_topics.py`
Hierarchical topic discovery script (multi-level clustering).

**Usage:**
```bash
python scripts/discover_hierarchical_topics.py \
  --broad-clusters 10 \
  --granular-threshold 0.85 \
  --min-broad-size 6 \
  --min-granular-size 2 \
  --compute-similarity
```

**Options:**
- `--broad-clusters` - Number of broad theme clusters (default: 10-15)
- `--granular-threshold` - Similarity threshold for granular sub-clustering (default: 0.80-0.90, higher = more specific)
- `--min-broad-size` - Minimum articles for broad topics (default: 6-10)
- `--min-granular-size` - Minimum articles for granular sub-topics (default: 2-3)
- `--compute-similarity` - Compute and store similarity matrix

**Output:**
- Discovers broad themes (Level 1) and granular sub-topics (Level 2)
- Creates hierarchical parent-child relationships
- Uses LLM for semantic topic naming at both levels

### 2. `scripts/kb_topic_discovery_runner.py`
Automated runner for perpetual operation.

**Features:**
- Checks for new/updated KB articles
- Runs topic discovery if new articles found
- Maintains rota schedule (fills gaps)
- Aggregates content for upcoming topics
- Regenerates rota if incomplete

**Integration:**
- Runs weekly on Mondays via `background_posting_monitor.sh`

## Technical Details

### Embedding Model
- **Model:** `intfloat/e5-large-v2`
- **Dimensions:** 1024
- **Normalization:** Yes (L2 normalized)

### Clustering Parameters

**K-means (Broad Themes):**
- Auto-detection: Tests k=5 to k=50 (or len/10)
- Uses silhouette score for optimization
- Random state: 42
- Typical: 8-15 clusters for broad themes

**Hierarchical (Granular Sub-topics):**
- Linkage: 'average'
- Metric: 'cosine'
- Distance threshold: 1.0 - granular_threshold
- Typical thresholds: 0.80-0.90 (higher = more specific sub-topics)
- Can discover very granular topics (e.g., "Line Widths and Balance in Tartan Design")

**DBSCAN:**
- eps: 0.5 (cosine distance)
- min_samples: 3 (configurable)

### Topic Naming

**LLM-Based Semantic Naming:**
- Uses Ollama (llama3.2:latest) for semantic understanding
- Analyzes article content to understand meaning and concepts
- Generates contextualized, meaningful topic names
- Not keyword-based - understands relationships and themes
- Examples:
  - ✅ "Line Widths and Balance in Tartan Design" (semantic)
  - ❌ "Tartan Kilt Your" (keyword-based, avoided)

### Diversity Constraints

- **Minimum Similarity Gap:** 0.7 (configurable)
- **Lookback Window:** 6 weeks (configurable)
- **Type Bonus:** +0.15 for different topic type
- **Category Bonus:** +0.1 * (1 - overlap) for different categories

### Content Aggregation

- **Chunk Selection:** Top 5 chunks by relevance (configurable)
- **Ranking:** Cosine similarity to topic centroid
- **Combination:** Preserves article structure with separators

## Maintenance

### Regenerating Embeddings

If KB articles are updated, embeddings are regenerated automatically when:
- Topic discovery runs (weekly)
- New articles detected
- Articles updated since last discovery

### Updating Topics

Topics can be manually updated:
```sql
UPDATE kb_topics
SET topic_name = 'New Name',
    priority = 10,
    is_active = TRUE
WHERE id = 5;
```

### Regenerating Rota

Rota can be regenerated:
- Via API: `POST /api/kb-topics/regenerate-rota`
- Automatically: If rota has gaps (< 48 weeks scheduled)

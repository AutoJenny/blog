Facebook Channel

{{ get_status_badge('complete')|safe }}

Facebook is the primary social media channel for automated content publishing. The system supports posting to multiple Facebook pages and includes full automation for weekly content.

How It Works

Single gate: Facebook posts are published only through scheduled_posting_executor.py. The manual API and workflow action return 403 and do not publish. This ensures all posts go through Matrix v1.1 weekday validation (Phase C1).

Posting Process

Content is posted to Facebook using the Facebook Graph API:

  1. Content is prepared (image, caption, metadata)
  2. Image is uploaded or made publicly accessible
  3. Post is created via /photos endpoint
  4. Post ID is stored in posting_queue.platform_post_id

Multiple Pages

The system posts to both Facebook pages:

  • Scotweb CLAN - Primary page
  • CLAN by Scotweb - Secondary page

Both pages are posted to simultaneously, with independent success/failure tracking.

Content Types

Facebook currently supports:

  • Weekly Words & Phrases - Automated (words, phrases, insults)
  • Culture / Heritage - Monday (culture_fact) and Thursday (heritage_fact) with authoritative headers (UNDERSTANDING SCOTLAND, SCOTTISH HERITAGE)
  • Product posts - Commerce posts; price is never shown in preview or publish (policy)
  • Message, authority_short, depth_long - Text-only or image posts as per Matrix
  • Other Content Types - 🔴 Not yet implemented

Culture & Heritage formatting

Culture (Monday) and heritage (Thursday) posts use a shared formatter so preview matches publish:

  • Header: UNDERSTANDING SCOTLAND (culture_fact) or SCOTTISH HERITAGE (heritage_fact), then two newlines, title, one newline, body.
  • Newlines: runs of 3+ blank lines are collapsed to 2; no trailing spaces; at most one trailing newline.
  • Product captions: price is stripped from preview and published text.

Technical details: Facebook culture/heritage formatting (docs), Preview matches publish. Run parity check when format logic changes: PYTHONPATH=. python3 scripts/prove_preview_publish_parity.py --platform facebook --weeks 2 --qa-format.

UI Access

Facebook content can be managed through:

  • Monitoring Dashboard - View posting status
  • Publication Dashboard - Overall publication status

Automated Posting Control

The system includes a master switch to control all automated posting to Facebook (and all other platforms).

  • Location: Homepage "Calendar & Planning" panel (top right) or Calendar page header
  • Function: Enable/disable all automated posting with a single toggle
  • Manual Trigger: "Publish Now" button allows manual publishing when automation is off

When the switch is OFF, no posts will be published to Facebook (or any platform) until the switch is turned back on or manually triggered.

For details, see: Automated Posting Control System Documentation

Configuration

Facebook credentials are stored in the platform_credentials table:

  • page_id - Primary page ID
  • page_access_token - Primary page access token
  • page_id_2 - Secondary page ID
  • page_access_token_2 - Secondary page access token

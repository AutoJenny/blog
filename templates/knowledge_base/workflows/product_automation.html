Product Post Automation

{{ get_status_badge('complete')|safe }}

Product posts are now fully automated, following the same workflow system as weekly content. Posts are created 1 week in advance, processed through workflow stages, and published automatically at scheduled times.

How Product Post Automation Works

Product posts follow the same automated workflow as weekly content:

Schedule → Create Draft → Workflow → Ready → Published

Step 1: Create Product Posts (1 Week Ahead)

Script: automated_product_post_creator.py

What it does:

  • Reads active schedules from daily_posts_schedule table
  • Calculates upcoming posting slots (next 7 days)
  • Selects products that haven't been posted recently (prioritizes products with images)
  • Creates draft posts in posting_queue table
  • Prevents duplicate posts for the same time slot

Example: Schedule says "Saturday 15:00" → Finds available product → Creates draft post for next Saturday 15:00

Step 2: Execute Workflow

Script: automated_product_post_workflow.py

What it does:

  • Finds draft product posts in posting_queue
  • Executes workflow stages:
    • format_for_facebook - Extracts product data (name, description, image, URL)
    • generate_caption - Generates caption using LLMService (30 style variations)
    • add_hashtags - Adds hashtags to caption
    • optimize_for_facebook - Uses product image URL directly
  • Updates status to ready when complete

Example: Draft post → Format data → Generate caption → Add hashtags → Use product image → Status = ready

Step 3: Schedule Posts

Script: automated_posting.py

What it does:

  • Finds ready product posts
  • Checks if scheduled time is coming up (within 30 minutes)
  • Sets exact scheduled_timestamp (with random delay for natural distribution)
  • Updates status to pending

Step 4: Publish Posts

Script: posting_executor.py

What it does:

  • Finds pending or ready posts where scheduled_timestamp <= now()
  • Posts to Facebook using product image and generated caption
  • Updates status to published
  • Stores Facebook post ID

Workflow Stages

Product posts use the same workflow system as weekly content:

Stage Substage What It Does
Content format_for_facebook Extracts product data from clan_products table
generate_caption Generates caption using LLMService with 30 style variations
add_hashtags Adds hashtags to caption
Imaging optimize_for_facebook Uses product image URL directly (no generation needed)
Publish publish_to_facebook Posts to Facebook using /photos endpoint

Configuration

Workflow Configuration

Defined in config/output_channel_stages.py:

('product', 'facebook'): {
    'stages': ['content', 'imaging', 'publish'],
    'substages': {
        'content': ['format_for_facebook', 'generate_caption', 'add_hashtags'],
        'imaging': ['optimize_for_facebook'],
        'publish': ['publish_to_facebook']
    }
}

Prompt Configuration

Product posts use standardized prompts from config/product_post_caption_prompts.py:

  • System Prompt: Defines role, rules, and output format
  • 30 Variation Styles: Heritage, Quality, Gift, Storytelling, Craftsmanship, etc.
  • Random Selection: Each post uses a random style for variety

Scheduling

Product posts use daily_posts_schedule table for recurring patterns:

  • Weekends Schedule: Saturday/Sunday at 15:00
  • TuesThurs5pm Schedule: Tuesday/Thursday at 17:00
  • Additional schedules can be added as needed

Background Monitor Integration

The background_posting_monitor.sh script runs every 5 minutes and executes:

  1. Create weekly content posts
  2. Execute weekly content workflows
  3. Create product posts (NEW) ✅
  4. Execute product post workflows (NEW) ✅
  5. Run automated posting scheduler
  6. Run posting executor

Status Flow

draft → ready → pending → published
  • draft - Post created, needs workflow execution
  • ready - Workflow complete, ready to schedule
  • pending - Scheduled, waiting for time
  • published - Posted to Facebook ✅

Key Differences from Weekly Content

Aspect Weekly Content Product Posts
Source Calendar (calendar_ideas table) Product catalog (clan_products table)
Scheduling Calendar JSON files (week-based) daily_posts_schedule (date-based)
Image Generated square image (1080×1080) Product image URL (from CDN)
Caption JSON with alternatives Plain text caption
Workflow Same stages Same stages

Database Queries

-- Check draft product posts
SELECT * FROM posting_queue 
WHERE content_type = 'product' AND status = 'draft';

-- Check ready product posts
SELECT * FROM posting_queue 
WHERE content_type = 'product' AND status = 'ready';

-- Check published product posts
SELECT * FROM posting_queue 
WHERE content_type = 'product' AND status = 'published';

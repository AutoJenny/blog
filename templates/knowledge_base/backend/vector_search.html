Vector Search System

{{ get_status_badge('complete')|safe }}

The Vector Search System provides semantic similarity matching across all content types in the system. It enables intelligent content discovery, context retrieval for LLM generation, and automatic matching of related content.

What Is Vector Search?

Vector search uses embeddings (numerical representations of text) to find content based on meaning, not just keywords. This allows the system to understand semantic relationships between products, categories, knowledge base articles, and blog posts.

Example: Searching for "Scottish tartan scarves" will find products, categories, and KB articles related to tartans, scarves, Scottish heritage, and similar concepts - even if those exact words aren't in the content.

How It Works

1. Content Chunking

Content from different sources is processed into chunks - normalized text ready for embedding:

  • Products - Name, description, specs, supplier info
  • Categories - Name, description, heritage data
  • KB Articles - Article content (some articles split into multiple chunks)
  • Producers - Supplier/producer information
  • Posts - Blog post content (theme posts)

2. Embedding Generation

Each chunk is converted to a 1024-dimensional vector using the intfloat/e5-large-v2 model:

  • Model: E5-large-v2 (HuggingFace Transformers)
  • Dimensions: 1024
  • Optimized for semantic search and retrieval

3. FAISS Index

All embeddings are stored in a FAISS index for fast similarity search:

  • Type: HNSW (Hierarchical Navigable Small World)
  • Location: data/vector_index/products_categories.faiss
  • Total Vectors: 2,117 (as of 2026-01-22)
  • Search Speed: <100ms for top-10 results

4. Similarity Search

When searching, the system:

  1. Generates an embedding for the query text
  2. Searches the FAISS index for nearest neighbors
  3. Retrieves metadata from the database
  4. Returns results with similarity scores

Database Schema

Primary Table: content_chunks

Stores all chunked content with embedding metadata:

  • chunk_type - Type: 'product', 'category', 'kb', 'producer', or 'post'
  • source_id - Reference to the source (product_id, category_id, etc.)
  • chunk_text - Normalized text content
  • metadata - JSONB with context (names, IDs, paths, etc.)
  • embedding_model - Model used (e.g., 'e5-large-v2')
  • embedding_dim - Vector dimensions (1024)
  • faiss_index_id - Position in FAISS index
  • last_embedded_at - Timestamp of last embedding generation

Maintenance

Regenerating Embeddings

To regenerate embeddings for specific content types:

# Products
python3 scripts/generate_embeddings.py --products

# Categories
python3 scripts/generate_embeddings.py --categories

# KB Articles
python3 scripts/generate_embeddings.py --kb

# Producers
python3 scripts/generate_embeddings.py --producers

# Posts
python3 scripts/generate_embeddings.py --posts

Incremental Updates

The system tracks last_embedded_at timestamps to support incremental updates. Changed content can be detected and re-embedded without full regeneration.

Technical Details

Embedding Model

  • Model: intfloat/e5-large-v2
  • Dimensions: 1024
  • Provider: HuggingFace Transformers
  • Library: sentence-transformers

FAISS Index Configuration

  • Type: HNSW (Hierarchical Navigable Small World)
  • M Parameter: 32 (connectivity)
  • efConstruction: 200 (construction quality)
  • efSearch: 50 (search quality vs speed)

Similarity Calculation

Similarity scores are calculated as: 1.0 / (1.0 + distance)

  • Range: 0.0 (no similarity) to 1.0 (perfect match)
  • Typical Good Match: >0.7 similarity
  • Excellent Match: >0.85 similarity

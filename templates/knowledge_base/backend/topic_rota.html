KB Topic Rota System

✅ Complete

The KB Topic Rota System is a perpetual, data-driven system that discovers recurring themes from Knowledge Base articles and creates diverse weekly schedules for social media content production.

Overview

This system automatically:

  • Discovers topics from KB articles using unsupervised clustering on semantic embeddings
  • Generates diverse weekly schedules ensuring non-repetitive, interesting content
  • Aggregates content from multiple KB articles for each topic
  • Feeds social media production processes for channel-specific formatting
  • Self-updates automatically when new KB content is added

How It Works

1. Hierarchical Topic Discovery

The system uses multi-level clustering to discover topics at different levels of granularity:

  • Level 1 - Broad Themes: Discovers major themes (e.g., "Tartan Patterns & Variations")
  • Level 2 - Granular Sub-topics: Discovers specific sub-themes within broad topics (e.g., "Line Widths and Balance in Tartan Design")
  • Uses LLM-based semantic naming (Ollama/llama3.2) to understand meaning, not just keywords
  • Creates hierarchical parent-child relationships between broad and granular topics
  • Analyzes all KB article chunks (696 chunks from 629 articles)
  • Groups semantically similar articles into topics
  • Classifies topic types (practical, historical, cultural, design, product, etc.)

Example Hierarchy:

  • 📌 Tartan Patterns & Variations (Level 1, 119 articles)
    • └─ Tartan Pattern Design and Layout (Level 2, 2 articles)
    • └─ Tartan Sett Arrangement Principles (Level 2, 6 articles)
    • └─ Tartan Design Creation and Customization Process (Level 2, 16 articles)

2. Diversity Scheduling (Enhanced 2026-01-23)

The rota generator ensures non-repetitive, interesting schedules with strong penalties to prevent similar topics from appearing consecutively:

  • Includes all topics: By default, generates a rotation including all topics (currently 71 topics)
  • Strong Consecutive Week Penalties:
    • Same topic type (e.g., both "design"): 70% penalty
    • Same parent topic (e.g., both Level 2 under same parent): 80% penalty
    • High semantic similarity (>0.75): 60% penalty
    • Moderate similarity (>0.65): 40% penalty
  • Calculating similarity between topics using embedding cosine similarity
  • Scoring diversity based on similarity to recent topics (4-week lookback, most recent weighted more heavily)
  • Giving bonuses for different topic types (+0.2) and parent topics (+0.15)
  • Enforcing minimum gaps between similar topics (similarity threshold: 0.65)
  • Prioritizing unused topics to ensure complete coverage
  • Safety Cap: Diversity score capped at 0.3 for consecutive similar topics

Rota Options:

  • Full Rotation (Default): 144 weeks (2.8 years) - includes all 144 topics
  • Custom Duration: Can generate shorter rotations (e.g., 52 weeks) if needed

3. Content Aggregation

For each scheduled topic, the system:

  • Retrieves all articles belonging to the topic
  • Ranks article chunks by relevance to topic centroid
  • Selects top chunks and combines them into aggregated content
  • Preserves article structure with clear separators

4. Social Media Production

Topics and aggregated content are exposed via API endpoints for social media production processes:

  • Get weekly topic schedule
  • Retrieve aggregated content for formatting
  • Access topic metadata (keywords, type, articles)

Production processes can then format content for different channels (Facebook, Instagram, Twitter, Blog) while maintaining the core topic and aggregated knowledge.

Database Schema

The system uses 5 database tables:

  • kb_topics - Discovered topics with embeddings and metadata
    • Includes hierarchical fields: parent_id, level, is_broad
    • LLM-generated semantic names and descriptions
  • kb_topic_similarity - Pre-computed similarity matrix for diversity
  • kb_topic_rota - Weekly schedule of topics
  • kb_rota_history - History for diversity tracking
  • kb_topic_content - Aggregated content for each topic

User Interface

Topic Rota Editor - Visual interface for managing the weekly topic schedule:

  • View all topics organized by parent groups
  • Drag-and-drop topics to schedule weeks
  • Auto-arrange topics with diversity constraints
  • Exclude/include topics from rota generation
  • Exclude entire topic groups at once
  • Track topic usage status (used/unused for content generation)
  • Reset used status when full cycle completes
  • Filter topics by search term or type

API Endpoints

All endpoints are under /api/kb-topics:

  • GET /rota - Get weekly rota schedule
  • GET /<topic_id>/content - Get aggregated content for topic
  • POST /discover - Trigger topic discovery
  • POST /regenerate-rota - Regenerate rota schedule
  • GET /topics - List all topics
  • POST /topic/<id>/exclude - Toggle topic exclusion
  • POST /topic/<id>/mark-used - Mark topic as used
  • POST /topics/reset-used - Reset all used flags

Usage

Initial Setup

  1. Run database migration: migrations/20260122_create_kb_topic_rota_tables.sql
    • Note: Hierarchical columns (parent_id, level, is_broad) are added automatically if missing
  2. Run hierarchical discovery (recommended):
    • python scripts/discover_hierarchical_topics.py --broad-clusters 10 --granular-threshold 0.85 --compute-similarity
    • Or single-level: python scripts/discover_kb_topics.py --method kmeans --compute-similarity
  3. Generate rota: POST /api/kb-topics/regenerate-rota
    • By default, generates 2.8-year rotation including all topics
    • Or specify: {"weeks": 52} for 1-year rotation

Ongoing Operation

The system runs automatically:

  • Weekly Discovery: Runs every Monday via background monitor
  • Rota Maintenance: Automatically fills gaps and aggregates content
  • Manual Triggers: Use API endpoints for manual discovery/regeneration

Key Features

  • Hierarchical Discovery: Multi-level topic discovery (broad themes + granular sub-topics)
  • Semantic Understanding: LLM-based topic naming understands meaning, not just keywords
  • Unsupervised Discovery: Topics emerge from data, not manual lists
  • Cross-Category Topics: Identifies themes spanning multiple KB sections
  • Complete Coverage: Rota includes all topics (2.8-year rotation by default)
  • Diversity Algorithm: Ensures non-repetitive, interesting schedules
  • Perpetual Operation: Self-updates as KB content changes
  • Channel Agnostic: Topics are abstract - formatting happens downstream

Technical Details

  • Embedding Model: intfloat/e5-large-v2 (1024 dimensions)
  • Clustering:
    • Level 1: K-means (auto-detected k, typically 8-15 clusters)
    • Level 2: Hierarchical clustering with tight thresholds (0.80-0.90 similarity)
  • Topic Naming: LLM-based (Ollama/llama3.2:latest) for semantic understanding
  • Similarity Metric: Cosine similarity between topic embeddings
  • Diversity Constraints: Minimum similarity gap (0.65, stricter), 4-week lookback (more focused)
  • Current State: 71 topics (25 Level 1, 46 Level 2), average 27.8 articles per Level 1 topic
  • Editor Interface: Topic Rota Editor - Visual drag-and-drop interface for managing topics and schedule

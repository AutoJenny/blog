Image Policy Overview

Purpose

This page summarises how images are handled across CLAN content and channels. It is not the authoritative policy. The authoritative source is:

docs/IMAGE_CAPABILITY_CHARTER.md

All channels, generators, previews, and publishers must comply with that Charter.

What this page is for

  • Help editors and operators understand what kinds of images exist
  • Explain why some images are generated, some sourced, some typographic
  • Point coders to the Charter for binding rules

Core principles (summary)

  • Images support credibility, not spectacle
  • Preview always matches publish
  • Product imagery is never generated
  • Generated imagery is illustrative, not documentary
  • Attribution and disclosure are handled consistently

See Image Capability Charter §2–§5.

Image classes used in the system

See Image Capability Charter §3 for full definitions.

  • Product photography — Product catalogue images only; no generation.
  • Public-domain historical images — Maps, engravings, archival material; attribution required.
  • Generated editorial illustrations — Atmospheric or symbolic visuals; no named historical figures; disclosure required.
  • Typographic cards — Text-first visuals for reassurance, language, or emphasis.
  • Diagrammatic / abstract images — Maps, timelines, or symbolic layouts without historical claims.

Channels and images (high level)

  • Facebook: Uses product images, weekly generated squares, and formatted text previews. Preview exactly matches publish.
  • Instagram: Image-first channel (in development). Uses the same image classes as other channels; format differs, policy does not.
  • Blog / Newsletter: Use model-aware imaging and/or sourced images with attribution and disclosure.

Where to find the rules

  • Authoritative policy: docs/IMAGE_CAPABILITY_CHARTER.md
  • Preview behaviour: docs/UNIFIED_CHANNEL_PREVIEW_SYSTEM.md
  • Weekly image generation: docs/WEEKLY_CONTENT_SYSTEM_TECHNICAL_REFERENCE.md
  • Facebook parity: docs/PREVIEW_FACEBOOK_MATCH_PUBLISH.md

Important note

If this KB page and the Image Capability Charter ever conflict, the Charter takes precedence.

For implementation routing, see docs/IMAGE_CAPABILITIES_INDEX.md.

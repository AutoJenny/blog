Product Posts

{{ get_status_badge('in_progress')|safe }}

Product Posts are social media posts that feature products from the Clan.com catalog. These are short-form social media posts (not blog articles) designed for platforms like Facebook and Instagram. The system is partially functional but uses outdated/isolated systems that need updates to align with current architecture.

⚠️ System Review Required: Product posts currently use older patterns that don't align with the current weekly content implementation. See Product Posts System Review for detailed analysis and update plan.

What Are Product Posts?

Product Posts are social media content that:

  • Feature Products: Showcase products from the Clan.com catalog
  • Social Media Format: Short captions, product images, hashtags
  • AI Content Generation: Use Ollama LLM to generate engaging product descriptions
  • Direct Posting: Posted directly to social platforms (Facebook, Instagram, etc.)
  • Queue Management: Schedule and manage multiple posts in a queue

Current System Architecture

1. Product Selection ✅

Status: Current - Uses `clan_products` table correctly

  • Browse products by category from the Clan.com catalog
  • View product details (name, SKU, price, description, images)
  • Search and filter products
  • Select a product for content generation

Endpoints: /launchpad/api/syndication/categories, /launchpad/api/syndication/products

2. AI Content Generation ⚠️

Status: Outdated - Uses custom LLM integration, not standardized

  • Current: Direct Ollama API calls instead of standardized LLMService
  • Current: Custom prompt templates in llm_prompts table (separate from weekly content)

Endpoint: /launchpad/api/syndication/generate-social-content

3. Scheduling ❌

Status: Outdated - Uses separate daily_posts_schedule table, not integrated with calendar

4. Posting ⚠️

How It Currently Works

  1. Select Product: Browse and select a product from the catalog
  2. Generate Content: Use AI to generate an engaging social media caption (direct Ollama calls)
  3. Add to Queue: Add the generated post to the posting queue
  4. Schedule: Set date and time for posting using daily_posts_schedule table
  5. Publish: System posts to Facebook at scheduled time (or manually trigger)

How It Should Work (Target Architecture)

To align with current architecture, product posts should:

  1. Use Workflow System: Integrate with automation_core.execute_substage() and output_channel_stages.py
  2. Use Calendar Scheduling: Integrate with calendar JSON files or unified scheduling system
  3. Use Standardized LLM: Use LLMService with intercept_context logging
  4. Use Unified Posting: Use execute_publish_to_facebook() from automation system
  5. Add Automation: Create automated scripts (creator, workflow, executor) like weekly content
  6. Appear in Dashboard: Integrate with publication schedule view

UI Access

Product Posts can be managed through:

  • Product Posts Interface - Main interface for creating and managing product posts
  • Monitoring Dashboard - View posting status and automation events
  • Publication Dashboard - Overall publication status (product posts may not appear here yet)

Database Storage

Product posts are stored in the posting_queue table:

  • content_type = 'product' - Identifies as product post
  • product_id - Links to product in catalog
  • generated_content - JSON with caption and metadata
  • scheduled_date and scheduled_time - When to post
  • status - Draft, Ready, Published, Failed
  • platform - Facebook, Instagram, etc.

Difference from Generated Posts

Product Posts (this page) are social media posts about products - short posts for Facebook/Instagram.

Generated Posts (under Blog Posts) are blog articles generated from products - full-length articles for the blog website.

Both use products as source material, but create different types of content for different channels.

Configuration

Product posts currently use:

  • Database: posting_queue table for storage
  • AI Service: Ollama (local LLM) for content generation (direct calls, not standardized)
  • Product Data: Clan.com catalog integration
  • Facebook API: Graph API for posting (both pages)
  • Scheduling: daily_posts_schedule table for recurring patterns (outdated)

Product posts should use (target architecture):

  • Workflow: config/output_channel_stages.py - Define stages for product → Facebook pipeline
  • LLM Service: LLMService from blueprints/llm_actions with intercept_context
  • Caption Prompts: config/product_post_caption_prompts.py - Standardized prompt configuration
  • Scheduling: Calendar JSON files or unified scheduling system
  • Posting: execute_publish_to_facebook() from automation_execute.py
